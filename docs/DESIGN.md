# support-memory 设计卡（M1）

## 要解决的问题
客服 Agent 换一个对话就忘了用户说过的偏好；记住的东西又可能带着手机号这类隐私，或者串到别的账户。这个项目演示：跨对话记住偏好、账户之间隔离、用户能清除、存之前先遮住隐私，并给出一份照着就能装起来的交接说明。

全部数据虚构（品牌青柚家电），不调用真实模型。Python 3.10+，只用标准库（含 sqlite3）。

## 目录
```
supportmemory/
  __main__.py   # 命令行
  store.py      # SQLite 记忆存储：按账户存偏好，带写入时间
  prefs.py      # 从用户消息里按规则识别偏好（确定性，无模型）
  redact.py     # 存储前遮住手机号、身份证号、详细地址样式的串
  bot.py        # 假客服：读订单和偏好，回答“列出订单”等问题，回答附订单号
data/orders.json      # 两个虚构账户的订单（已发货 / 未发货混合）
docs/HANDOFF.md       # 实施交接说明（纯文字，给不写代码的人照做）
scripts/smoke.sh      # 在空的临时目录里照 HANDOFF 跑一遍
tests/
```

## 偏好（只做这三种，规则识别）
1. 订单筛选：如“以后只看未发货的”“只看已发货的” → `order_filter = unshipped | shipped`；“看全部订单” → 清掉这项。
2. 回答长短：如“回答简短点” → `brevity = short`；“详细一点” → `long`。
3. 称呼：如“叫我王先生” → `salutation = 王先生`。称呼里若含手机号等，按 redact 规则处理后再存。
识别不到就什么都不存。一句话可以命中多条。

## 行为
- `chat --account A --session S "消息"`：识别偏好并存（先遮隐私）；再由假客服回答。回答第一行写明用了哪些偏好（例如“按你之前的设置，只列未发货订单”），方便验收。
- 新对话（新 session、甚至重启进程）同一账户：偏好仍生效。
- 不同账户：互不可见。
- `forget --account A [--key order_filter]`：清一项或全部；之后回答恢复默认。
- `show --account A`：列出该账户当前偏好和写入时间（不含任何原始消息）。
- 存储只存偏好键值，不存原始消息。redact 必须在写入前执行。
- `export --out PATH`：跑内置的演示脚本（下一节的三段对话加一段隐私示例），把每一步的输入、回答、当时存储内容写成一个 JSON，供网站演示页使用；不含绝对路径、主机名、用户名。

## 必须写的验收测试（tests/）
1. 账户 A 说“以后只看未发货的”，新建 session、新建进程（重新打开数据库）后问“列出订单” → 只返回 A 的未发货订单号。
2. 账户 B 问同一句 → 返回 B 的全部订单，看不到 A 的偏好。
3. A `forget` 后再问 → 返回 A 的全部订单。
4. A 说“叫我王先生，电话 13812345678” → 存储里的任何值都不含这串数字（检查数据库全部内容，不只检查返回值）；回答里也不回显号码。
5. 不含偏好的消息不产生写入（数据库行数不变）。
6. `export` 的输出不含绝对路径、主机名、用户名，重复运行逐字节一致。
7. `scripts/smoke.sh` 在临时空目录里从零跑通，并演示“漏放 orders.json → 按 HANDOFF 的恢复步骤 → 恢复正常”。

证明测试不是摆设：把 redact 调用挪到写入之后、把账户隔离的 WHERE 条件去掉，各自跑一次测试，贴出失败，再改回。

## HANDOFF.md 要写的
给不写代码的实施人员：需要什么（Python 版本）、从空目录开始的每一步命令、导入样例数据、试问三句话和预期回答、常见故障三条（缺数据文件、Python 版本太低、数据库被锁）各自的现象和恢复办法、怎样清除一个用户的全部记忆。

## 不做
不接真实模型；不做网页（网站演示页另做）；不做多语言；不做向量检索。
